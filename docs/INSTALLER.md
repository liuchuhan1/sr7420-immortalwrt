# USB 安装、启动和回退

目标流程是：保留原厂系统，在原厂完成基础硬件初始化后，使用 kexec 启动 USB 根文件系统；关机拔盘后再开机回到原厂。

**原厂 root shell 内的 GitHub 在线安装和手动切换已通过实机验收。原厂网页一次上传安装包和持久启动 hook 仍未实现；请勿把本仓库的文件改名为原厂 `.bin` 上传。**

[下载 r2 Release](https://github.com/liuchuhan1/sr7420-immortalwrt/releases/tag/usb44-r2-20261118) · [一行安装](INSTALL-R2-ONE-LINE.sh) · [一行启动](BOOT-R2-ONE-LINE.sh) · [实测报告](../reports/r2/online-install-test-r2.json)

## 安装前

- 已有获得授权的原厂 root shell。在线入口不负责提权或开启维护访问；目前只验证了原厂 Linux `5.4.196` 和设备树型号 `ZTE 133`。
- 原厂能够通过 HTTPS 访问 GitHub。准备一块允许清空的 U 盘，并先备份数据。
- 一行安装方式要求只有一块符合条件的可移除 USB 盘，且有可核对的序列号。多盘、无序列号、已挂载或正在作为系统使用的盘会被拒绝。
- 切换会中断当前网络。电脑应接 LAN1–3 并使用 DHCP，提前准备 SSH 客户端，以便在新系统启动后的 120 秒窗口内确认。

## 1. 从 GitHub 在线安装到 U 盘

打开 [原厂一行安装命令](INSTALL-R2-ONE-LINE.sh)，复制最后一整行到原厂 root shell。**其中的 `--erase-single-usb` 明确授权清空唯一符合要求的 U 盘。**

命令内置首次下载所需的公开根证书，从固定 Git 提交下载入口，再下载并校验固定 r2 Release 的 launcher 与系统包。全程启用 HTTPS 证书校验，不需要预放离线包、CA 证书或 SHA256 工具，也不调用容易匿名限流的 GitHub API。不要改成关闭 TLS 校验的下载命令。

系统包下载并校验成功后才开始重新分区。安装器读取本机原厂 Wi-Fi 固件、校准、板级数据和 MAC，写入这台设备的 U 盘系统；这些设备数据不会从公共镜像中获取。

安装结束默认仍留在原厂系统。再次执行会验证并复用完整的同版系统，不再下载系统包或格式化，但仍会下载并校验小型 launcher。

## 2. 手动切换到已安装的 U 盘系统

复制 [一行启动命令](BOOT-R2-ONE-LINE.sh) 的最后一整行，在原厂 root shell 执行。它会重新下载并校验入口和 launcher，然后调用 `boot`；不会执行安装或格式化。当前需要恰好一块可移除 USB 盘及已校验的系统。

一行入口会在退出时清理临时脚本，不能假定安装后当前目录留有 `sr7420-install-online.sh`。只有已经另外下载并保留了该脚本时，才使用下面的短命令：

```sh
sh sr7420-install-online.sh install --erase-single-usb
sh sr7420-install-online.sh boot
```

如需安装后立即切换，可在完整一行安装命令的最末尾，或上述短安装命令末尾追加 `--boot`。目前实测是先安装，再单独执行 `boot`；二者调用相同安装器路径，未另外重装一遍测试合并调用。

## 3. 在 120 秒内完成本次启动确认

切换后电脑应从 DHCP 取得 `192.168.77.x` 地址。LuCI 为 `http://192.168.77.1`，SSH/LuCI 用户名 `root`、密码 `password`。LAN1–3 为 LAN，LAN4 为 WAN。

先确认电脑已经取得 DHCP 地址、LuCI 可以登录且网络配置页有写权限，然后从电脑登录新系统：

```sh
ssh root@192.168.77.1
```

在本次启动的 SSH 会话中检查根分区，应为可写的 USB ext4 根系统，再执行：

```sh
mount | grep ' on / '
test -w / && echo 'root is writable'
sr7420-usb-confirm
```

**每次 USB 启动都要在 120 秒内完成外部确认，才会取消回退倒计时。** 本地服务启动、只打开 LuCI、上次已经确认，都不等于本次已确认。`sr7420-usb-confirm` 会复查 LAN、管理服务和可写 USB 根分区；应在外部检查通过后执行。

未确认时软件守护按已有回退逻辑尝试重启原厂；CPU/总线完全卡死时，软件守护不能保证恢复。无线默认是两个开启的 `immortalwrt` 开放热点，设备标签为 `QCN6224 2.4G` 和 `QCN6224 5G`。

## 4. 失败处理和返回原厂

- 下载、证书或 SHA256 校验失败：停止安装并检查网络和完整日志，不要关闭校验强行继续。
- 多盘、已挂载或序列号不符：核对目标盘；需要指定设备时使用下面的离线 launcher 流程，不要凭 `/dev/sdX` 名称猜盘。
- 上次启动未确认：会保留 `boot-pending` 并拒绝再次启动。先检查 USB `/boot-state/` 日志，解决原因后才在完整一行启动命令末尾，或保留的入口/launcher 的 `boot` 命令末尾手工添加 `--retry`。
- 返回原厂：先正常关机/重启并停止 USB 根系统，再拔盘。**运行中的 USB 根文件系统不能热拔。** 当前未安装原厂持久自启 hook。

## 离线安装与指定 U 盘

r2 的 GitHub 在线下载、安装、重复复用及本次发布归档的启动已经实测。默认内核模块仓库为 `sr7420-kmods-r2`，`apk update` 成功，报告见 [在线安装测试记录](../reports/r2/online-install-test-r2.json)。原厂持久入口仍未验证，当前不要配置无人值守切换。

1. 下载同一 Release 的 `sr7420-usb44-launcher.tar.gz`、`sr7420-usb44-offline.tar.gz` 和 `SHA256SUMS`。
2. 在可信电脑先核对 SHA256，解开 launcher。把离线包放到其中 `sr7420-usb.sh` 旁边。保留 launcher 内完整的 `tools/`、`sha256` 和辅助脚本。
3. 把这些文件放在原厂系统可执行的目录中，不能放在接下来要格式化的目标 U 盘上。
4. 在原厂 root shell 运行 `sh sr7420-usb.sh detect`，确认总盘和物理序列号。
5. 安装命令为 `sh sr7420-usb.sh install --device /dev/sdX --serial YOUR_USB_SERIAL --erase`。这里的设备名和序列号必须替换为 detect 的实际结果；这一步会清空匹配的目标 U 盘。
6. 离线包不存在时脚本使用固定 HTTPS 地址下载，并校验该发行包 SHA256。已有完整、校验通过的系统会直接复用。安装完成本身不会切换内核。
7. 待可以承担网络中断并能正常重启恢复时，再运行 `sh sr7420-usb.sh boot --device /dev/sdX --serial YOUR_USB_SERIAL`。上次启动没有通过就绪检查时，必须排查日志后手工添加 `--retry`。

`/dev/sdX` 和 `YOUR_USB_SERIAL` 是说明中的替换标记，不是预先选定的设备。未验证原厂持久入口，因此 launcher 中的自启辅助脚本不会自行安装。

## 2026-11-18 实测结果

| 检查 | 结果 |
| --- | --- |
| 无预放离线包，从 GitHub 下载、校验后安装 | 通过，约 61.78 秒 |
| 再次安装复用原系统 | 通过，约 14.66 秒，不再下载系统包或格式化 |
| 独立安装校验 | 通过，约 14.69 秒 |
| 下载 404、包 SHA256 错误、目标分区已挂载 | 均在擦盘前停止，三项测试前后启动分区 SHA256 不变 |
| 随后启动新安装的 r2 归档 | 可写 ext4 根、外部 DHCP、SSH、LuCI 登录和 UCI 写权限通过 |
| 无线及软件源 | 两个 radio 启动、默认开放 SSID、r2 软件源通过；`apk update` 可见 11468 个不同软件包 |
| 外部就绪确认 | 通过，本次启动在回退窗口之后仍正常运行 |

安装、重复复用、独立校验、启动是分别执行的。组合 `install ... --boot` 未另做一次完整重装测试。耗时取决于网络和 U 盘。无线客户端连接/吞吐、硬件加速、交换机独立冷启动和双核不属于本次验收。详见 [实测报告](../reports/r2/online-install-test-r2.json)。

## 开发者：重新生成一行入口

在可信电脑执行；`--ref` 仅接受已公开的完整提交 SHA。默认不加 `--install` 时只生成检测命令，`--boot` 需要与 `--install` 一起使用：

```sh
python3 tools/online_install_command.py --ref 67bd8e37323dc81135e23e577e3aa610c40408b5 --install
```

一行入口较长，是因为原厂缺少 CA bundle 和 SHA256 工具，需要带上首次 HTTPS 下载所需的公开根证书。请完整复制，不要截断证书内容。

## 已实现的源码

- 识别 USB 总盘、物理 USB 路径、可移除标记、序列号、容量、只读标记及挂载状态。
- 新盘只有明确指定匹配序列号和 `--erase` 才允许重新分区；在线入口的 `--erase-single-usb` 会先确认只有一块符合条件的盘，再传入其设备名、序列号和 `--erase`。授权某一块测试盘不等于授权清空任意插入的盘。
- 已有完整且校验通过的同版系统直接复用；优先离线包，在线下载校验成功后才开始分区。
- 使用独立、有容量上限的 tmpfs 缓存，避免原厂 20 MiB `/tmp` 容不下安装包；检查可用内存。
- HTTPS 下载跟随重定向，重定向不降级 HTTP；校验固定发行 SHA256。
- 从当前这台设备读取原厂 firmware/BDF/完整 cal，保留 2.4 GHz 和 5 GHz 映射；不把其他设备的校准数据写进去。
- 在本机用原厂 MAC 生成设备 DTB，公开模板不带本机 MAC。
- 切换前处理原厂 WLAN、PCI bus master/MSI，并把 kexec 等工具复制到 RAM。
- 切换前写 `boot-pending`；新系统只有在外部电脑验证 USB 根分区、DHCP、SSH 和 LuCI，并通过 SSH 执行 `sr7420-usb-confirm` 后才清除。未清除时原厂自动启动逻辑应跳过 USB，等待手动 `--retry`。
- 新系统启动阶段日志写 USB 的 `/boot-state/`，120 秒软件看门狗在没有收到本次启动的外部管理确认时尝试正常重启回原厂。

本机接口和管理进程就绪本身不会取消回退。外部验收通过后，以已登录的 SSH 会话执行 `sr7420-usb-confirm`。该脚本复查 LAN、服务及可写 USB 根分区，并写入包含本次 boot ID 的临时确认标志；旧标志和只有本机就绪的状态都不能取消倒计时。每次 USB 启动均需要新的外部确认。CPU/总线完全卡死时，软件看门狗不能提供恢复保证。

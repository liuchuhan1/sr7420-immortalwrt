# USB 安装和回退：实现范围

目标流程是：保留原厂系统，在原厂完成基础硬件初始化后，使用 kexec 启动 USB 根文件系统；关机拔盘后再开机回到原厂。

**整条流程仍未完成验收。当前没有可通过原厂网页一次上传的安装包，也没有验证过的原厂持久启动 hook。请勿把本仓库的文件改名为原厂 `.bin` 上传。**

## 已实现的源码

- 识别 USB 总盘、物理 USB 路径、可移除标记、序列号、容量、只读标记及挂载状态。
- 新盘只有明确指定匹配序列号和 `--erase` 才允许重新分区。授权某一块测试盘不等于授权清空任意插入的盘。
- 已有完整且校验通过的同版系统直接复用；优先离线包，在线下载校验成功后才开始分区。
- 使用独立、有容量上限的 tmpfs 缓存，避免原厂 20 MiB `/tmp` 容不下安装包；检查可用内存。
- HTTPS 下载跟随重定向，重定向不降级 HTTP；校验固定发行 SHA256。
- 从当前这台设备读取原厂 firmware/BDF/完整 cal，保留 2.4 GHz 和 5 GHz 映射；不把其他设备的校准数据写进去。
- 在本机用原厂 MAC 生成设备 DTB，公开模板不带本机 MAC。
- 切换前处理原厂 WLAN、PCI bus master/MSI，并把 kexec 等工具复制到 RAM。
- 切换前写 `boot-pending`；新系统只有在外部电脑验证 USB 根分区、DHCP、SSH 和 LuCI，并通过 SSH 执行 `sr7420-usb-confirm` 后才清除。未清除时原厂自动启动逻辑应跳过 USB，等待手动 `--retry`。
- 新系统启动阶段日志写 USB 的 `/boot-state/`，120 秒软件看门狗在没有收到本次启动的外部管理确认时尝试正常重启回原厂。

本机接口和管理进程就绪本身不会取消回退。外部验收通过后，以已登录的 SSH 会话执行 `sr7420-usb-confirm`。该脚本复查 LAN、服务及可写 USB 根分区，并写入包含本次 boot ID 的临时确认标志；旧标志和只有本机就绪的状态都不能取消倒计时。每次 USB 启动均需要新的外部确认。CPU/总线完全卡死时，软件看门狗不能提供恢复保证。

## 尚待完成

1. 验证原厂 `/supgrade.html` 后端接受的安装格式，或找到配置恢复的、可恢复且可验证的持久启动入口。
2. 新的 r2 发布归档尚未再次重启实测；其基础 r2 系统的静态 kexec、USB 模块启动、LAN、DHCP、SSH/LuCI 已通过。
3. 自启/卸载/回退在每种故障阶段的端到端测试。

原厂配置恢复目前只证明能够配置维护访问；不能把它当作已验证的任意安装器执行接口。原厂固件有完整性/签名封装，不能直接沿用另一型号的打包头。

`.in` 文件是构建输入，包含明确的发行 URL/SHA 占位符。它不是已经可用的发布安装器。当前也不应该设置无人值守自启。

要回原厂，请先正常关机/重启并停止 USB 根系统，再拔盘。运行中的根文件系统不能热拔。

## USB44 r2 实验预发布

r2 离线包和启动器已生成，默认内核模块仓库为 `sr7420-kmods-r2`，校验结果见 `reports/r2/usb-artifact-verification-r2.json`。运行中的 r2 USB 系统已通过网口/DHCP/SSH/LuCI 验证，新的重新打包归档尚未再次启动验收。原厂持久入口仍未验证，当前不要配置无人值守切换。

1. 下载同一 Release 的 `sr7420-usb44-launcher.tar.gz`、`sr7420-usb44-offline.tar.gz` 和 `SHA256SUMS`。
2. 在可信电脑先核对 SHA256，解开 launcher。把离线包放到其中 `sr7420-usb.sh` 旁边。保留 launcher 内完整的 `tools/`、`sha256` 和辅助脚本。
3. 把这些文件放在原厂系统可执行的目录中，不能放在接下来要格式化的目标 U 盘上。
4. 在原厂 root shell 运行 `sh sr7420-usb.sh detect`，确认总盘和物理序列号。
5. 安装命令为 `sh sr7420-usb.sh install --device /dev/sdX --serial YOUR_USB_SERIAL --erase`。这里的设备名和序列号必须替换为 detect 的实际结果；这一步会清空匹配的目标 U 盘。
6. 离线包不存在时脚本使用固定 HTTPS 地址下载，并校验该发行包 SHA256。已有完整、校验通过的系统会直接复用。安装完成本身不会切换内核。
7. 待可以承担网络中断并能正常重启恢复时，再运行 `sh sr7420-usb.sh boot --device /dev/sdX --serial YOUR_USB_SERIAL`。上次启动没有通过就绪检查时，必须排查日志后手工添加 `--retry`。

`/dev/sdX` 和 `YOUR_USB_SERIAL` 是说明中的替换标记，不是预先选定的设备。未验证原厂持久入口，因此 launcher 中的自启辅助脚本不会自行安装。
